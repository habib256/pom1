# POM1 command-line flags

Full reference for headless / scripted runs. Implementation: **`CliDispatcher.cpp`**. Emulator architecture (mutex order, peripherals, `ctest` pins) → [`CLAUDE.md`](../CLAUDE.md).

Three phases: **A** boot-time, **B** first-frame preset overrides, **C** deferred — fire after the 15-frame card plug-in, in command-line order. Example: `--load 0300:foo.bin --run 0300 --paste keys.txt` composes. Malformed verbs log `[CLI] ERROR:` and exit 1.

| Flag | Phase | Effect |
|------|-------|--------|
| `--help` / `-h` | A | Print the flag list (`kCliFlagHelp[]` in `CliDispatcher.cpp`) and exit 0. Kept in sync with this table and with the parser by ctest `cli_flags_sync`. |
| `--list-presets` | A | Print `kMachinePresets[]` and exit. |
| `--preset <N\|name>` / `-p` | A | Index or case-insensitive substring (first match). |
| `--preset-file <path>` | A | Boot a machine described by an **external preset file** instead of a `kMachinePresets[]` row — the other half of the plumbing `--cmd-port` opened: with one POM1 is driven from outside, with this it is *configured* from outside. Format and rationale: [`COMMAND_PORT.md`](COMMAND_PORT.md)'s sibling, [`src/PresetFile.h`](../src/PresetFile.h). A line-based `key = value` file opening with `pom1-preset 1`; card names are exactly `--enable`'s, aliases included (pinned by ctest `cli_dispatcher_smoke`). Dependencies are closed before validation (`cards = codetank` gets you `tms9918`) and the result is checked against `CardTopology` in the mode the FILE declares — `mode = fantasy` is how a machine says it multiplexes on purpose, since an external preset has no `PresetId` for `isFantasyPreset()` to answer from. An unknown key or card is an **error** and the whole preset is refused: a typo must not quietly boot a different machine. Wins over `--preset`; `--enable`/`--disable` still layer on top. Deliberately its own flag rather than an extra index — `kMachinePresets[]` is read by 57 sites and renumbering it is the wide refactor `TODO.md` declines. |
| `--preset-dir <path>` | A | Where to discover external preset files (`*.preset`), instead of the `presets/` directory [`ResourceLocator`](../src/ResourceLocator.h) resolves. `--preset-dir ""` discovers **none** — how a test isolates itself from whatever the developer keeps in their own `presets/`, since otherwise one broken file there would turn the repository's own suite red (`headless_preset_matrix` boots everything `--list-presets` reports). Read straight off `argv` before the rest of the command line, because `--list-presets` prints from the registry and exits inside the parser. Files are loaded in filename order: the index a preset gets is the key its saved window layout is stored under. |
| `--terminal` | A | Force-enable Terminal Card (`127.0.0.1:6502`). |
| `--cmd-port <N>` | A | **Headless dev-only**: open the scripting control channel on `127.0.0.1:N` (1-65535). Implies `--headless`. One request line in, one reply line out (`OK …` / `ERR …`); the verbs mirror the flags in this table — `load`, `run`, `step`, `break`, `snapshot-save` — plus the ones a one-shot command line cannot express: `key`, `expect`, `screen`, `peek`, `poke`, `reset`, `cycles`. Bound to loopback only, off unless asked, and not a stable API: it is test plumbing. It exists because the only other way to steer a running POM1 was the Terminal Card's telnet socket, which carries the keystrokes and the `$D012` echo down one wire — a harness had to sleep to know the machine was ready and parse the echo to know a command had finished. `expect` blocks on the emulated display instead. Protocol: [`COMMAND_PORT.md`](COMMAND_PORT.md); implementation: [`src/CommandPort.h`](../src/CommandPort.h); client + launcher: [`tools/pom1_control.py`](../tools/pom1_control.py). |
| `--telemetry-port <N>` | A | Dev-only: open the telemetry side channel on `127.0.0.1:N` (1-65535). Binary frame-delimited bridge for automated game testing — the game writes state to `$C440-$C443`, an external harness reads it + drives input. See [`TELEMETRY_SIDE_CHANNEL.md`](TELEMETRY_SIDE_CHANNEL.md). |
| `--telemetry-log <path>` | A | Dev-only: tee the telemetry outbound frame stream (`0xAA <len16> <payload>`…) to a binary file for golden-trace CI (no live harness needed — diff against an expected capture). Implies enabling the port (default `:6503` unless `--telemetry-port` also given). |
| `--dump-gen2-frame <path>` | A | Headless one-shot: render the GEN2 HGR framebuffer (280×192) to a PNG, then exit — automated **graphics regression** (golden-image diff). Implies `--headless`. Combine with `--preset 11` (or `--enable hgr`) + `--load`/`--run` to capture a program's output. The render path is the same software rasteriser the GUI uses, so the capture is pixel-identical. Logs `[GFX] GEN2 frame WxH hash=0x… -> path` — an FNV golden you can assert without diffing files. |
| `--dump-tms-frame <path>` | A | Same, for the TMS9918 framebuffer (288×216, incl. the R7 border). Pair with `--preset 9` (or `--enable tms9918`). |
| `--dump-after-cycles <N>` | A | Deterministic settle for `--dump-*-frame`: run exactly N emulated cycles (host-independent) before the capture, instead of the wall-clock `--dump-settle-ms`. The run is built on a **Deterministic** controller: the emulation thread never executes a cycle, so the Monitor's boot, `--load`/`--run` and every `--paste` are all counted inside N — nothing runs in real time before it (not with `--cmd-port` or `--telemetry-port`, which steer a live machine). **Use this for regression** so the golden is stable across machines (e.g. `2000000`). |
| `--exit-after-cycles <N>` | A | **Headless one-shot**: after the deferred verbs (`--load`/`--run`/`--paste`…), run exactly N emulated cycles on the calling thread (Deterministic controller, as for `--dump-after-cycles`), log `headless run complete — N cycles, PC=$xxxx`, exit 0. Implies `--headless`. Host-independent "boot and live" budget — `tools/test_headless_presets.py` (ctest `headless_preset_matrix`) boots all 13 presets with it and asserts the CPU parked in the Woz Monitor. With `--paste-at-cycle` it is the replay budget (later injections are skipped). |
| `--dump-settle-ms <N>` | A | Wall-clock settle (default 1000) before a `--dump-*-frame` capture. Quick/interactive; non-deterministic — prefer `--dump-after-cycles` for CI. |
| `--tape <path>` | A | Preload + auto-Play on boot (any preset). Default WOZ talk loads only with the POM1 Fantasy preset. Formats: `.aci` `.wav` `.aiff` `.ogg` `.mp3` `.flac`. `.aiff` (Uncle Bernie's **ACIace** output) is always a program tape, like `.aci` — pair it with `--enable xaci` and type `C500R` then `RX RX`. |
| `--save-tape <path>` / `--save-tape-format <aci\|wav>` | A | Dump deck on clean shutdown. SIGINT/SIGTERM triggers `~MainWindow_ImGui`. |
| `--cpu-max` | A | Pin `executionSpeed = 1 000 000` cycles/frame. Beats `--speed`. |
| `--audio-latency <ms>` | A | Output cushion in ms, clamped `[20, 250]` (default ≈17 ms = 256 frames × 3 periods at 44.1 kHz). miniaudio keeps 3 periods and stretches each — fewer, larger wake-ups. Raise it on a box that cannot always refill the ring in time: on a **Raspberry Pi kiosk** the symptom is continuous crackle and the miss happens in the OS scheduler, not in the emulator (120 is a good start; `packaging/raspberrypi` sets it from `/etc/pom1-kiosk.conf`). No effect on WASM — the browser owns the buffer. Impl: `AudioDevice::setPreferredLatencyMs`, applied before `Memory` builds the device. |
| `--fullscreen` | A | Open the OS window fullscreen on the primary monitor, whatever the preset layout says, and **re-assert it after every preset switch** (each `loadPresetLayout` restores its own saved geometry). Lets a kiosk session run a **bare X server** with no window manager at all — one compositor/WM copy per frame less. Unticking *Settings ▸ Fullscreen* releases the hold; the forced state is deliberately **not** written back into `ini/preset_NN.size`. Desktop only. |
| `--headless` | A | Run with **no GLFW window / GL / ImGui** — for CI & scripted runs on a display-less box. Default 64K machine + execution speed + telemetry + all Phase-C deferred verbs (`--load`/`--run`/`--paste`/`--step`/`--sd-*`/`--snapshot`/`--break`); idles until SIGINT/SIGTERM. Applies `--preset` / `--enable` / `--disable` (RAM + cards + BASIC ROM, plugged immediately) — e.g. `--preset 11` plugs GEN2 for headless HGR game tests. Pairs with `--telemetry-port` / `--telemetry-log` (see `tools/test_telemetry_lockstep.py`, `tools/test_headless_preset.py`). |
| `--speed <cycles/frame>` | B | Override (1× = 17045, 2× = 34091). |
| `--enable <card>[,…]` / `--disable <card>[,…]` | B | Rewrite deferred plug list. Names: `aci, xaci, sid, sid-se, microsd, tms9918, a1io-rtc, hgr, cffa1, krusader, wifi, terminal, jukebox, codetank, pr40, gt6144, iec`. `iec` cascade-enables microSD; `xaci` (aliases `extended-aci`, `aci2` — Uncle Bernie's extended `$C500` PROM page) cascade-enables `aci`, and `--disable aci` cascade-unplugs it. Mutex rules enforced. `--disable krusader` is a no-op (ROM unload needs hard reset). Run after `--terminal`. |
| `--sid-chip <6581\|8580>` | B | Swap chip; libresidfp replays last register state. |
| `--jukebox-jumper <ram16\|ram32>` / `--jukebox-chip <flash\|eeprom>` | B | Juke-Box ROM window + chip mode. |
| `--codetank-jumper <lower\|upper>` / `--codetank-rom <path>` | B | Pick 16 kB half of 32 kB 28c256 / override the default probe (`roms/codetank/Codetank_ARCADE.rom`, then the legacy `roms/codetank.rom`). `--enable codetank` auto-schedules `--enable tms9918`; `--disable tms9918` cascade-unschedules CodeTank. |
| `--iec-disk <path>` | B | Mount a `.d64` (174 848 B standard 1541 image) on the P-LAB IEC daughterboard's virtual drive 8 at startup. Overrides the default `disks/iec/dev8.d64` probe. Failure logs `[IEC] WARN: --iec-disk: failed to mount <path>`. |
| `--silicon-strict` / `--no-silicon-strict` | B | Force-flip TMS9918 `siliconStrictMode` (paranoid 40c — drops VRAM writes < 40 cycles in Mode I+sprites, 4/6/6/2c in text/multicolor/no-sprites/blank, 4K/16K via R1 bit 7 — see `sketchs/doc/Programming_TMS9918.md` §17 Bug N°1). Contract: passing POM1 strict ⇒ silicon-safe. May 2026 ramp: 16→24→40c after Galaga sprite tables and LOGO BIRD/Demo redraws kept showing artefacts at every previous level. Default = ON for every preset except the Multiplexing Fantasy ones; the override survives the first frame but a later preset switch resets to default. Hardware menu has a runtime toggle and the status bar shows `STRICT` / `FANTASY`. |
| `--dram-refresh` / `--no-dram-refresh` | B | Force-flip the Apple-1 DRAM-refresh stall (4/65 cycles stolen from the CPU; the video beam keeps running, so beam-race GEN2 demos drift as on real DRAM silicon). Independent of `--silicon-strict` so headless beam-race captures can isolate it. Default follows the preset (ON except Multiplexing Fantasy); the override survives the first frame but a later preset switch resets to default. Runtime toggle in the Hardware → Silicon Strict inspector. |
| `--display-field-sync` / `--no-display-field-sync` | B | How PB7 (`$D012` busy) is driven. **Default OFF**: a fixed countdown of `CPU_HZ/60` = 17045 cycles armed by the write — what every shipped program and golden image is validated on. **ON**: busy until the next 60 Hz field boundary (65 × 262 = **17030** cycles), modelling the fact that Woz's terminal has no framebuffer — the text recirculates through a shift register scanned at the video rate, so a character can only be latched when the scan reaches the cursor, and PB7 stays busy until the next pass. Throughput is identical either way (consecutive writes stay exactly one field apart, so the documented 60 characters/second holds — pinned by `terminal_timing_smoke` §3); only *where* the wait falls moves. Unlike its neighbours **no preset ever arms it**: the phase-locked model is reasoned from the schematic, not measured on a terminal section. Runtime toggle in Hardware → Silicon Strict inspector. See [`src/TerminalTiming.h`](../src/TerminalTiming.h). |
| `--vram-noise` | B | Power on the TMS9918 VRAM with true mt19937 **noise** (what warm P-LAB DRAM shows on a cold boot) instead of POM1's lenient bistable `$FF`/`$00` default. Surfaces uninitialised-SAT / ghost-terminator bugs — games that skip a defensive SAT fill render fine on the POM1 default and break on real silicon. Forces a power-on reset. See [`TMS9918-SPRITE_INIT.md`](../sketchs/doc/TMS9918-SPRITE_INIT.md) §4.2. |
| `--tms-frameflag-hostile` | B | Model worst-case TMS9918 silicon where the status **frame flag (F) never registers** to the CPU, so an unbounded `BIT $CC01 / BPL` vblank poll hangs. Reproduces the TMS_Rogue black screen POM1 otherwise cannot (it sets F deterministically). Deliberately **not** folded into `--silicon-strict` — it would hang the shipped Snake/Galaga naked `WAIT_VBLANK`s. Runtime toggle in the Hardware → Silicon Strict inspector. |
| `--ram-poison <HH>` | B | Fill system RAM with the deterministic sentinel byte `HH` (hex) instead of `$00` at power-on. Half of the read-before-write harness for the TMS9918 "works on POM1, breaks on silicon" cause #2 — uninitialised RAM reads that a zero-fill silently makes harmless. Forces a power-on reset. |
| `--ram-trap` | B | Arm the **read-before-write trap**: log the first CPU read of any RAM cell the program never wrote this run, over `[0,$2000)` + `[$E000,$F000)` (Parmigiani's high bank). Pairs with `--ram-poison`. Forces a power-on reset. |
| `--load <addr>:<path>` | C | Rewrite reset, `hardReset` + `start`. Hex/decimal addr. Repeatable. **Extension-routed**: `.txt` `.hex` `.apl` `.mon` `.tur` go through the hex parsers — Wozmon by default, the line-structured one for `.tur`, and **Intel HEX** for any file whose *shape* says so (`:LLAAAATT<data>CC`, detected by count/type/checksum, never by name, so an Intel HEX called `.txt` still loads and a Wozmon dump called `.hex` is untouched) (multi-zone dumps load every zone, the file's own `AAAA:` prefixes and `R` suffix win over `<addr>`); anything else is a raw binary written at `<addr>`. `.apl` is Uncle Bernie's canonical Apple-1 name — a `.apl` that loaded as 6143 raw bytes instead of a 1962-byte program is the bug this routing fixes. `.tur` (TurboType) loads too: POM1 injects RAM directly, so the file's serial receiver is skipped and its own CRC-CCITT checker verifies the image and starts the program. |
| `--run <addr>` | C | `EmulationController::jumpTo()`. |
| `--paste <file>` | C | ≤4096 chars to keyboard queue (`\n`→CR, printable ASCII). |
| `--paste-at-cycle <N> "<keys>"` | C | **Headless only.** Inject `<keys>` to the keyboard queue when the emulated CPU reaches cumulative cycle `N` (underscores in `N` allowed: `5_000_000`). Repeatable; sorted by cycle, order-independent. Forces the deterministic cycle-driven run (segments at each injection), so two runs land on the **same** frame regardless of host speed — drives a TMS9918 game past its title screen into the sprite playfield, then `--dump-tms-frame`, for an `--vram-noise` ON-vs-OFF A/B (same filtering as `--paste`). Pairs with `--dump-after-cycles N` (settle/budget); without it, the capture happens right after the last injection. Directives past the budget are warned + skipped. |
| `--step <N>` / `--trace-brk` | C | Step N + BRK trace dump. |
| `--play` / `--rec` / `--rewind` | C | Cassette transport. `--rec` = `armRecording()` (no $C000 wait). |
| `--sd-mkdir <path>` / `--sd-put <h>:<g>` / `--sd-get <g>:<h>` | C | SD fixture seeding. |
| `--rtc-freeze "YYYY-MM-DD HH:MM:SS"` | C | Set `A1IO_RTC::rtcOffsetSeconds` (host rate keeps ticking). |
| `--snapshot-save <path>` | C | Write current state (RAM + card-enabled flags + per-card payload via `Peripheral::serialize`) to `<path>`. Format: see `SnapshotIO.h`. |
| `--snapshot-load <path>` | C | Restore state from a `.snap` written by `--snapshot-save`. Per-card serialize hooks default to no-op until each card migrates its internal state — see `Peripheral.h`. |
| `--break <addr>` | C | Arm M6502 PC-matched halt (single breakpoint). Fires *before* the instruction at `<addr>` executes; CPU stops itself, logs `[CPU] WARN breakpoint hit at $XXXX` once. Cleared by `hardReset()` (preset switch). Continue with manual `stepCpu()` past the address followed by `startCpu()`, or `clearCpuBreakpoint()` + `startCpu()`. |

Two telnet tests auto-launch POM1 from repo root: `tools/test_aci_telnet.py`, `tools/test_sdcard_subdir_navigation_telnet.py`.

`tools/test_gfx_regress.py` does **golden-image graphics regression** via the `--dump-*-frame` capture (launch headless → render → sha256 vs a committed golden; `--update` regenerates it). Frozen fixtures live in `tests/gfx/`; pinned by the `gfx_regress_*` ctest.
