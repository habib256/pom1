# POM1 testing reference

How the suite is built and run, the two lanes, per-module coverage, the
architecture ratchets — and the catalogue of load-bearing pins, each with the
defect it exists to prevent.

Split out of [`CLAUDE.md`](../CLAUDE.md), which keeps the short version and
points here. Doc map → [`doc/README.md`](README.md).

---

`ctest` from `build/` (native-only, opt-out `-DPOM1_ENABLE_TESTS=OFF`). Inventory in `tests/CMakeLists.txt`; `ctest -N` lists exact names. CMake never invokes `dev/codetank/Makefile`; those are developer-only build steps. Tests load whatever artefact lives under `software/`.

```bash
ctest                       # full suite (~5–30 s wall time; Klaus + TMS9918 tests dominate)
tools/coverage.py --gate    # per-module line+branch coverage (nightly CI job)
ctest -L emulator           # the release gate — green with no cc65 and no editors
ctest -L devtools           # editors, DevBench/cc65 pipeline, BASIC compilers
ctest --output-on-failure
ctest -R klaus -V
```

**Coverage is measured per MODULE, never as one percentage** (`-DPOM1_COVERAGE=ON` + `tools/coverage.py`, nightly `coverage` job in `ci.yml`). A single figure over the 44 500 measurable lines averages a cycle-exact 6502 against 14 400 lines of ImGui drawing no test binary links: it moves for the wrong reasons and is improved by testing whatever is easiest. Measured on the septembre-2026 nightly — **cpu 93.9 %, parsers 93.7 %, topology 90.8 %, snapshot 89.0 %, memory 79.8 %, devices 64.8 %, platform 61.9 %, control 42.0 %, devtools 24.4 %, ui 4.2 % of 14 687 lines**. **Two of those rows moved a long way and it was the same cause**: `devices` 52.4 → 64.8 % and `control` 34.3 → 42.0 %, bought by putting the seven `_telnet` harnesses into `ctest` — they drive whole cards through a real emulator, which is exactly the code no unit test reaches. Nothing was written to raise those numbers; work that was already written started running (the `ui` row was 2.4 % before the decision-extraction chantier; the seven seams it produced are at 100 % of lines, and what is left uncovered there is the ~13 900 that draw). **The extracted seams stay in the `ui` module on purpose** — `MODULES` in the script lists them explicitly — because the row is meant to say how much of the UI layer's LOGIC is tested, and reclassifying those lines elsewhere would improve the figure by moving the work, which is the gaming a per-module table exists to prevent. **A `constexpr` seam needs runtime calls as well as `static_assert`s**: instrumentation cannot see a compile-time evaluation, so `ShortcutTable.h` read as 30 % covered while every one of its properties was in fact PROVED, more strongly than a runtime assert can (a static_assert cannot be skipped). `shortcut_table_smoke` now asserts each property twice — once folded, once through a `volatile` launder (and a function pointer for the no-argument overload) — which is what took that file to 100 %. Reach for the same trick in the next pure header, or its row will understate what it guarantees. Only the first four are GATED (`THRESHOLDS` in the script: 90/90/85/85, set just under what the suite measures, so they catch a module LOSING coverage — a branch arriving without its case); the rest are reported, because a floor under 2.4 % UI coverage would be a number pretending to be a promise. The `ui` row is the quantified version of TODO.md's chantier 3. `llvm-cov`/`llvm-profdata` must come from the clang that compiled the tree — a mismatch says only "unsupported coverage format version" — so the script resolves them by that compiler's major version.

**Windows reserves 1 MB of stack per thread; Linux and macOS give 8.** `CMakeLists.txt` raises MSVC's reserve to 8 MB (`/STACK:8388608`) because POM1 is written against the larger one and the gap is not theoretical: `sizeof(EmulationSnapshot)` is **260 KB** and `sizeof(EmulationController)` **261 KB**, so a test holding a controller and three snapshots by value is over the 1 MB line by arithmetic. Two tests died that way on Windows alone for five days — **with no output at all**, because the CRT discards a buffered stdout when the process dies, so `--output-on-failure` showed nothing and it read as an inexplicable segfault. The way to find this from a machine that is not the one crashing is `clang -Wframe-larger-than=32768` over the test sources: it printed 2 130 928 B and 801 344 B for the two that crashed and 267 824 B for the one that passed. Reach for it before believing a Windows-only crash is a logic bug.

**Two lanes, and every declared test carries exactly one of them** (`LABELS`,
assigned at the bottom of `tests/CMakeLists.txt` from the `POM1_DEVTOOLS_TESTS`
list). `emulator` (90 tests) is what an emulator release must pass, and it is
green on a machine with **no cc65** — the toolchain-dependent tests in it
(`lib_micro_tests`) skip with 77 rather than fail. `devtools` (28) is the
development environment's own lane: the editors, the DevBench/cc65 pipeline,
the BASIC compilers and their 6502 runtime. The rule for the list is
**subject**, not name: a test is `devtools` when it compiles a source from the
devtools set that `tools/check_architecture.py` guards, or drives cc65 —
`bench_basic_inject_smoke`, `bench_logo_inject_smoke`, `applesoft_*`,
`codetank_claudio_gate`, `lib_micro_tests` and the `dev/` assembly lints all
assert *emulator* behaviour and stay in the gate despite their names. **Absent
from the list means `emulator`**, deliberately: an unlabelled devtools test
lands in the release gate and turns it red on a cc65-less machine, where the
other default would drop a test out of the gate in silence. `ci.yml`'s Linux
job runs the two lanes as two steps — the same 148 tests, at no extra cost,
with a red step that names which product broke.

Load-bearing pins worth knowing:

- **`klaus_6502_functional`** — Klaus Dormann's 6502 functional test. Gates all CPU refactors (functional only — no cycle counts).
- **`cpu_harte_smoke`** — Tom Harte "65x02 ProcessorTests" (`tests/cpu/harte_6502.bin`, 100 cases × 151 documented opcodes). **Cycle-exact** per-opcode oracle; complements Klaus by pinning page-cross/branch penalties + decimal-mode ADC/SBC + PLP/RTI P-bits.
- **`cpu_interrupt_smoke`** — IRQ/NMI line timing (7-cycle entry, vectors, pushed-P B bit, edge-cleared NMI, RTI restore).
- **`headless_preset_matrix`** — boots all 13 presets with `--headless --preset N --exit-after-cycles 2000000` (`tools/test_headless_presets.py`, reads `--list-presets` so the count is never hardcoded) and asserts exit 0, no `ERROR` log line, and the CPU parked in the Woz Monitor (`$FF00-$FFFF`). The one test that walks `applyHeadlessConfig`'s whole card fan-out (RAM profile, jumpers, plug cascades, Parmigiani evictions, every card's reset + bus registration) — 3 s for the lot. `--exit-after-cycles` is what makes a headless run *finish*; before it the only exits were a signal or a `--dump-*-frame`.
- **`gen2_journal_snapshot_smoke`** — *does a rewind actually replay the beam?* The GEN2's mid-frame soft-switch flips live in a per-frame journal, serialised into the snapshot as `GEN2VID` (v5+) precisely so a restore keeps them — `MemorySnapshot.cpp` says a restored beam-split frame would otherwise "lose its per-line flips and show the plain end-of-frame latch". **Nothing tested that claim**: the snapshot tests check the section EXISTS and that its name does not collide, the beam tests render splits but never save one. This journals a mid-frame TEXT flip, publishes it at the rollover, snapshots, restores into a fresh machine, and compares the RENDERED PIXELS. Its §4 is a control that re-renders the restored machine with the journal thrown away and asserts the picture changes — without it the whole test would pass against a snapshot that lost the journal. That control earned its place twice: it caught a fixture where the text page was filled with `$20`, an **inverse** space that renders as a solid white block, pixel-identical to the all-bits-set HGR fill it was meant to contrast with (`$A0` is the normal space); and it caught the GEN2's randomised power-on scanner phase making the split land on a different line each run — the test now disables it the way the headless CLI path does, and DERIVES the split line from the journal instead of assuming one.
- **`gen2_beam_geometry_smoke`** — the GEN2 adopting the shared beam clock, proved EXHAUSTIVELY rather than by sampling: every cycle of a whole 262-line frame and of a whole 312-line one (37 310 in all), each compared against the pre-change formula **re-derived inside the test** rather than called — asking the new code to agree with itself proves nothing. The two engines each had their own cycle→(line, x): the TMS9918 through `pom1::beamPosAt`, the GEN2 through a private port of POM2's `Apple2Display`. They now share one clock. **The sweep earned its keep on the first run**: routing the column through `beamPosAt`'s `x` was wrong, because `x` is zeroed outside the active region while `forEachBeamSegment` SORTS events by `(scanline, byteCol)` — VBlank events included, and those are exactly the ones that set the state the next frame starts from, so an unstable sort would have reordered them. That is why `BeamClock.h` gained `lineTickAt` (the within-line ordinal, defined during blanking) and `rawLineAt` (the unclamped line), with `beamPosAt` re-expressed on both. Cycle 12506 of a 262-line frame is where it showed up.
- **`gen2_chargen_smoke`** — the GEN2 character generator against Table 2 of Bernie's spec, on BOTH paths: the IIe char ROM and the built-in 5×7 fallback used when that ROM is not found. Every assertion is an equivalence the table states (`$80-$9F` draws what `$C0-$DF` draws, `$00-$3F` is its inverse, `$40-$7F` alternates the two), so it holds for any glyph artwork. It exists for Bernie's *"block of 'O' looking characters"*: the fallback decoded a normal byte as `b & 0x7F` and drew `$80-$9F` as the no-glyph box, and the ROM path drew the IIe's MouseText for `$40-$7F`. Mutation-checked: each defect reintroduced fails 92 and 130 checks.
- **`input_movie_smoke`** — issue #40's foundation: an input movie recorded on a LIVE machine (DRAM refresh on, keys typed in real time) replays to the same state on a fresh live machine and on a deterministic one, and a tampered movie reports Diverged. The program logs each key with the loop counter at the moment it read it, so equal logs mean the keys landed on the same turns of the loop, not merely in the same order. Also pins the file format (round trip, 7 refusals) and the session policy (due keys, stops, verdicts). The replay machines start with DRAM refresh OFF: the setting and its phase come back through snapshot v7's `RUN` section — skip restoring it and the live replay diverges (checked by mutation). Checked by hand in the GUI: a recorded `E000R` / `PRINT 1+1` session replayed "verified".
- **`deterministic_run_smoke`** — a `Deterministic` controller reaches the same state after the same calls however long the host sleeps between them. The headless driver used to build a Live controller, whose thread runs the CPU in real time from construction and again after every `--load`/`--run` until the first `runCyclesSync` stops it: `--dump-after-cycles N` meant N plus a host-timed head start — a few hundred cycles on an idle desktop, unbounded on a loaded CI runner (TODO.md carried it as "`--paste-at-cycle` promet un déterminisme qu'il n'a pas"). The script — write a program, jump to it, queue a key, run 1 M counted cycles — is played with the host sleeping 0 ms then 3 × 120 ms: Deterministic ends byte-identical (64 KB + registers, counter 1 009 both times) with the key delivered; **Live, the control, diverges** (1 009 vs 17 330), so the test cannot pass against a controller that never ran. Foundation for input movies (issue #40).
- **`program_card_sniff_smoke`** — a program that addresses the GEN2's soft switches gets the GEN2 from wherever it is loaded. Dropping Bernie's `vsplits.apl` from outside `software/Graphic HGR/` ran it on the default machine, which has no graphics card: its V-blank wait read `$C25x` for an HST0 flag nothing would set, and it spun forever behind a blank screen — "it loads, then it hangs". Pins the byte pattern (absolute data instructions on `$C250-$C257`; JSR/JMP and neighbouring addresses do not count), Bernie's file parsed as POM1 parses it, and **no false positive** across every shipped program in another card's folder or the games (69 of them). Surveyed when written: 122 shipped programs (`software/` + `sdcard/`), 18 detected — exactly the 18 of `software/Graphic HGR/`, `vsplits.apl` included.
- **`gen2_field_pacer_smoke`** — the GEN2 window shows ONE emulated field per refresh. It drew the latest completed field, so jitter on either clock (emulation slices ~1 ms, host refreshes) made some refreshes see no new field and the next see two: Bernie's fine scroll "staggering along". Pins `Gen2FieldPacer`'s policy step by step (margin 2, one step per refresh, repeat only when nothing is ready, skip only when four are queued, restart on a new timeline), `pick`/`compose`, the end-state fold, and the claim itself by a deterministic simulation of both clocks over 120 s at 60 Hz: showing the latest field gives 297 / 1 048 / 2 010 refreshes that do not advance by exactly one field at 0.5 / 2 / 4 ms of jitter; the pacer gives 5 / 6 / 7 — the clock drift between 60.055 and 60 Hz, which no display policy removes. Measured in the real app on `vsplits` (temporary trace, 20 s): 1 229 single steps and one skip, where the latest-field form would have shown 37 hiccups.
- **`gen2_vsplits_smoke`** — Bernie's own vertical-split demo (`software/Graphic HGR/vsplits.apl`, his program bytes unmodified) run on the real core for 200 fields. Each field's TEXT scanlines must be exactly one 32-line band, one line below the previous field's, starting on the line the program itself counted to (its zero-page `$2C`); at the top, row 0 must read `@ABCDEFGH…`. The only program in the tree that crosses 6502 timing, HST0, the soft-switch journal and the renderer end to end. A second pass runs it through the real `SnapshotPublisher` in slices of 700-5 900 cycles and renders every field that reaches the ring: 200 consecutive seqs, each band one line below the last — the pacer can only show every field if the ring holds every field. Invariants, not a golden: the power-on scanner phase is random, the motion is not. A journal dated one line late fails on the first field.
- **`gfx_regress_gen2_testcard`** — headless golden-image graphics regression (`--dump-gen2-frame` + sha256 vs committed golden PNG; TMS9918 counterpart `--dump-tms-frame`). Harness `tools/test_gfx_regress.py` skips if Python3 / `build/POM1` absent. **It is the FIRST test in the suite to execute the POM1 binary** — all seven `--pom1` sites are declared after it — so it absorbs the cold start none of the others ever see: on Windows the on-first-execute virus scan plus paging a freshly linked exe and its DLLs off disk. Measured over 24 Windows CI jobs: 20 between 1.1 s and 2.2 s, then 5.7 s, 8.5 s, 9.3 s and one past 61 s — a tail of one job in six, belonging to this test alone, since `headless_preset_matrix` launches POM1 thirteen more times right behind it and never shows it. It had the TIGHTEST budget of any POM1-launching test (60 s against their 120-600) while paying for all of them; now 120 s, above the harness's own 90 s `--timeout` so the harness fires first and can print what POM1 said. **Two harness lessons, both paid for**: it ran `subprocess.run` with `DEVNULL` and no timeout, so the one artefact that could say where POM1 stopped was thrown away and ctest killed *python* rather than the emulator; and it printed its duration only on failure, which is a distribution nobody can see until it crosses a threshold — that is how a 60 s budget survived under a 9 s observation. It now prints the elapsed time on a PASS too, and says so past 5 s.
- **`basic_compiler_smoke`** — the Applesoft "BASIC compiler" (`src/BasicTokeniserApplesoft.*`, `basicc` tool, [`doc/BASIC_COMPILER.md`](BASIC_COMPILER.md)): compiles `3DHat.apf` to a 6502 image (tokenized program `$0801` + launcher `$0280` = `JSR SETPTRS;JMP NEWSTT`) and runs it injection-free on **both** GEN2 HGR and TMS9918, asserting the float 3-D plot fills the framebuffer. Re-pins the two interpreter entry points per card (TMS `$4596`/`$46F2`, GEN2 `$9D96`/`$9EF2`) — a ROM rebuild that shifts them fails here.
- **`basic_native_codegen` / `basic_native_run` / `basic_native_bench`** — the **native** BASIC→6502 compiler (`src/BasicCompilerApplesoft.*`, runtime `dev/lib/basicrt/`, [`doc/BASIC_COMPILER.md`](BASIC_COMPILER.md)): integer **and** binary32-**float** phases (incl. `SIN`/`SQR`/`INT`). Codegen unit pins (strength reduction, native FOR/GOTO/GOSUB, graphics ABI, float ops via `fp_*`, the temp-fusing peephole) + a cc65-gated end-to-end run that builds the standalone binary (loads/runs at `$0300`, no interpreter), runs it vs the interpreter, asserts **same framebuffer + native faster** (~22× integer compute, ~4.5× pixel-bound, ~2.0× float ceiling), and **compiles+runs the real `3DHat.apf` native** (transcendentals + `HCOLOR=0` hidden-line erase). `basic_native_bench` prints the size+speed-by-program-type table. Both skip (77) without cc65. **GEN2 standalone code shares RAM with the framebuffer, so it must fit `$0300–$1FFF` (cfg: BSS moved to `$0200`); the peephole's ~640 B saving is what lets 3DHat fit.**
- **`basic_float_runtime`** — the standalone **binary32 software-float** runtime (`dev/lib/basicrt/basicrt_float.s`, the FP-phase foundation, no Applesoft ROM): cc65-gated, assembles the runtime (with `-D FP_INT/FP_SQRT/FP_SIN`) and checks `fp_fromint16/toint16/add/sub/mul/div/cmp` + `fp_int`/`fp_sqrt`/`fp_sin` against the host IEEE `float`/`sqrtf`/`sinf` over a grid + random pairs (5736 cases). The transcendentals are feature-gated so they link only when used. Skips (77) without cc65.
- **`size_report_smoke`** — `tools/size_report.py` (ld65 map → per-region headroom incl. minus-the-C-stack, per-module byte table, `--why module` reference chains, `--min-headroom [REGION:]N` CI gate) **+ the DevBench archive-link model**: rebuilds the gen2c runtime `.lib` from `dev/bench/gen2c.json` (pins the spec's buildability), links a text-only program, asserts unused families are dead-stripped and the headroom math holds. Skips (77) without cl65+ar65.
- **`ehbasic_smoke`** — Lee Davison's Enhanced 6502 BASIC 2.22 at `$5000-$7FFF` (`roms/ehbasic.rom`, flashed into RAM, cold `5000R` / warm `5003R`). **The Apple-1 port is POM1's own** — none existed; upstream only ships a Kowalski-simulator stub with a fake ACIA — so `dev/ehbasic/src/` carries the PIA I/O and the entry stub while `basic.asm` stays untouched. There is therefore no published image to diff against and **running the interpreter IS the verification**: the test boots it, checks `PRINT 1/4` = `.25` and `PRINT SQR(2)` = `1.41421`, then types a `FOR` loop and runs it. It also asserts the string `DERIVED FROM EHBASIC` is still in the image — **that is a licence condition, not a style check** (EhBASIC requires it in any distributed binary; `dev/ehbasic/README.md` is the human-readable half). Rebuild with `dev/ehbasic/build_ehbasic.sh`.
- **`msbasic_smoke`** — Microsoft BASIC 6502 at `$E000` (`roms/msbasic.rom`, floating point, cold `E000R` / warm `E003R`). Boots the ROM on the emulated 6502, answers its two cold-start prompts and asserts `PRINT 1/4` yields `.25` — what no checksum can tell you. Also pins that `loadMsBasic` restores POM1's own Woz Monitor over the image's bundled copy (the file is a full 8 KB `$E000-$FFFF` EPROM image, kept intact so its sha256 still matches the published ROM) and that `unloadBasic` clears the FULL `$E000-$FEFF` window — MS BASIC is nearly twice Integer BASIC's size, so the old `$E000-$EFFF` clear left 3 KB of the previous interpreter behind when switching flavours. **The ROM is reproducible from public sources** — `dev/msbasic/build_msbasic.sh` rebuilds it from pinned mist64/msbasic + coopzone-dc overlay commits and asserts the hash; provenance, the four missing target-dispatch patches and the licence position are in `dev/msbasic/README.md`.
- **`measured_cpu_rate_smoke`** — the status bar's MEASURED clock rate (`EmulationController::getMeasuredCpuHz`) vs the pacer's target. Wall-clock based, loose bands; it separates "measured" from "target" and from the burst-rate bug (charging elapsed time only to slices that ran the CPU reads x1 as tens of MHz). Also pins that a parked CPU publishes 0 — the window only refreshes inside `runEmulationSlice`, which the park branch skips.
- **`rom_swap_reset_smoke`** — a card transaction that rewrites `$E000-$FFFF` (a preset's system-ROM profile, Krusader, the CFFA1 firmware) must re-vector through `$FFFC` before the CPU resumes. Without it the program counter is an offset into the image that was just replaced, and the new bytes decode from the wrong instruction boundary: preset 6 fell into Krusader's own BRK handler and printed a register dump instead of its prompt, ~2 nightly TSan runs in 3, because how far the provisional monitor had run is WALL-CLOCK dependent. The pin holds the RULE, not the symptom — the symptom is a race and cannot be pinned. Three halves: after a ROM-rewriting transaction with no `coldReset` the PC is the `$FFFC` vector **read back from the new image** (not an assumed `$FF00`); user RAM `$0200-$1FFF` survives byte for byte (`softReset`, not `hardReset` — a 6502 RESET clears no RAM); and the **control case**, a transaction that rewrites no ROM, leaves the PC exactly where it was, so a fix that reset unconditionally would fail too.
- **`lock_order_smoke`** — the mutex order (`stateMutex > keyboard.keyMutex > publisher.snapshotMutex`) is now ENFORCED, not just documented: `src/LockOrder.h` gives each lock a rank and asserts a thread only ever takes one strictly inside what it already holds. `PriorityMutex` carries the `State` rank; `keyMutex` and `snapshotMutex` are `pom1::RankedMutex<...>` (BasicLockable, so the six existing `lock_guard` sites only changed their template argument). Compiled out under `NDEBUG`, live in the test binaries (`-UNDEBUG`) and in Debug builds — and layout-identical either way, so no ABI hazard. The test **forks a child per inversion and reaps `SIGABRT`**, which is the point: a checker that never fires reads as coverage while providing none. It carries a control case for the same reason — a checker that aborted on *everything* would otherwise pass every assertion.
- **`doc_paths_sync`** — third guard of the `version_sync` / `imgui_pin_sync` family (`tools/check_doc_paths.py`): every source path the markdown cites in backticks must exist. 370 citations checked, resolved against the repo root, the citing document's own directory, `src/`, `dev/` and `dev/lib/` — those last three being the conventions the docs actually use. `CHANGELOG.md` is excluded whole (a changelog naming a file that has since moved is correct history, not drift), as are `EXTERNAL_ROOTS` (POM2, upstream demos, toolkit headers) and filename templates like `imgui_preset_NN.ini`. Replaces a manual pass — the git log already contains one that fixed 20 drifts by hand.
- **`action_pins_sync`** — fifth guard of the family (`tools/check_action_pins.py`): every `uses:` in `.github/workflows/` names a 40-hex commit SHA with the version it came from in a trailing `# vX.Y.Z` comment. `@v5` is not a version — it is a mutable pointer in someone else's repository, and these workflows carry the repo's secrets (`release.yml` builds, signs and publishes the downloads; `pages.yml` deploys the site). **Offline by construction**: it never asks GitHub whether a SHA exists, because a test that needs the network goes red on a train — it holds the SHAPE, and `.github/dependabot.yml` (monthly, grouped, rewrites SHA *and* comment together) holds the freshness. It also refuses one SHA commented as two different versions across files, which is a half-finished bump. Note `upload-artifact` is deliberately v4 on `ci.yml`/`pages.yml` and v5 on `release.yml`/`pi-borne.yml`: pinning is not upgrading.
- **`resource_probes_sync`** — fourth guard of the `version_sync` / `imgui_pin_sync` / `doc_paths_sync` family (`tools/check_resource_probes.py`): no POM1 source may spell its own `"x", "../x", "../../x"` walk. 241 files scanned, 5 allowlisted non-probe sites (MicroSD's guest-side traversal check, the four editors' "parent directory" browser row), each with its reason in the script. It replaces a review habit — the probes it removed disagreed on how far to climb and half of them had no exe-relative branch outside Windows — and it is verified in BOTH directions: reintroducing one probe fails the test.
- **`concurrent_frontends_smoke`** — the three production concurrency roles without ImGui or an audio backend. It gates what POM1 CONTROLS: `maxStateHoldNs` (100 ms; measured 18-68 ms) and `maxAudioCallbackNs` (50 ms; measured 7-33 µs), plus snapshot validity and the audio sample count. **`maxStateWaitNs` is a catastrophe bound (5 s = a hang), deliberately not a quality one.** At 500 ms it fired on a healthy GitHub Linux runner at 1.66 s while the max HOLD stayed at 16 ms — nobody held the lock too long, a waiter lost the scheduler — and on an idle 8-core Mac the same quantity already ranges 57-350 ms. It also does not detect what it was there for: disabling the `PriorityMutex` yield in `emulationLoop` and running eight times tripped 500 ms ONCE. What the yield actually buys is PROGRESS of the contending thread — topology swaps completed in the window, median ~117 with it against ~35 without, eight runs each; the distributions overlap on a single run (116 vs 45), so that is the measurement a future gate should be built on, not yet a threshold. Note the test had never once run on Linux CI: it arrived in the same commit that broke that build.
- **`d64_fuzz_smoke`** — hostile input against the 1541 disk-image reader, mutating a real formatted disk with files on it (random bytes almost never reach the traversal code). Invariants: mounting is decided by size alone, every traversal **terminates**, directory entries and file contents are bounded by the disk rather than by the numbers the disk contains, free blocks stay within the geometry, and reading leaves the image byte-identical. **It found both defects** `d64_parse_smoke` now pins — the counter-based chain walks and the unclamped BAM count. A 30 000-image campaign under ASan+UBSan is clean.
- **`snapshot_validate_smoke`** — the snapshot pre-flight (`pom1::outlineSnapshot` / `validateSnapshot` in `SnapshotIO.h`), pure: no `Memory`, no CPU, no file in the binary. Applying a snapshot writes **straight into the live machine, section by section**, so a file that went bad halfway left a HYBRID and reported a clean failure — truncating a real 116 933-byte snapshot to 200 bytes restored the CPU section, program counter and all, over RAM that was never replaced, and a PC pointing into a program that is not in memory is a machine that will run garbage. Rewind replays these same blobs. Seven sections pin the section walk, the magic/version gate (a future version is refused, never half-understood), truncation caught mid-header / mid-payload / at a boundary, a forged length checked against the bytes **remaining** (never `offset+length`, which wraps on wasm32), MEM's two legal lengths and nothing else, GEN2VID's event count bounded by the payload actually present (the count drives a `reserve()`), and that a rejected outline reports **no sections at all**.
- **`snapshot_fuzz_smoke`** — hostile input against that gate, enumerating **every** truncation of a realistic snapshot byte by byte (66 631 of them — the exact family that produced the hybrid machine, cheap enough to exhaust rather than sample) plus the usual mutation rounds aimed at the 32-bit length fields. Invariants: validate ⇒ outline ok, every section indexable inside the buffer, sections **tile** the file in order with no overlap and no unaccounted tail, every refusal explained, and determinism.
- **`pcm_file_smoke`** — the two cassette containers as pure functions (`PcmFile.h`, above), with the WAV/AIFF bytes built in the test rather than read from disk. Twelve sections: the signed/unsigned 8-bit split, 16/24/32-bit and float32, the channel mixdown, AIFF-C `sowt`/`fl32`, the 80-bit rate (including its absurd-value refusal), SSND's offset and a malformed one, COMM's smaller-wins rule, the wrap-safe chunk-size guard, the frame cap (exercised through a `maxFrames` parameter — the real cap is 172.8 M frames and crossing it for real would allocate the better part of a gigabyte inside a unit test), the file-size cap, and that unsupported widths are refused **before** any frame is decoded.
- **`pcm_file_fuzz_smoke`** — hostile input against those two parsers: the surface where POM1 reads a **binary** file a user picked, and where chunked-format length arithmetic goes wrong. Same dual shape as the memory-image fuzzer, with the mutator aimed at 32-bit length fields. Its invariants are the ones the consumer needs: a rejected parse is inert and explained, an accepted one has a rate the pulse decoder can divide by, the frame count is bounded by the cap **and** by the input (so no crafted header makes a small file allocate a large buffer), every sample is finite, truncation is never silent, and no input is accepted as both a WAV and an AIFF. **It found two real defects** — the unbounded WAV sample rate and the NaN/Inf passthrough, both now pinned as `pcm_file_smoke` §11-§12.
- **`memory_image_fuzz_smoke`** — hostile input against the loader, in two shapes from one source (`tests/memory_image_fuzz_test.cpp`). The default build is a **deterministic** driver (fixed seed, so a failure reproduces byte for byte): it replays a corpus of real dump shapes, mutates it toward the punctuation that steers the parser, and holds **every** result to the header's contract — 64 KB containment, `byteCount` agreeing with the spans, no writes on a rejected image, `zones()` matching span for span, output bounded by input (amplification is a DoS shape, not a parse), and an identical result on a re-parse (purity). `-DPOM1_FUZZERS=ON` puts the same checks behind `LLVMFuzzerTestOneInput` for the long ASan campaign — the deterministic driver is the **default** rather than the fallback because Apple clang ships no libFuzzer, so a fuzz-only gate would silently not run on macOS. A 60 000-input campaign under ASan+UBSan found no memory fault; the defect it did surface (the `strtol` platform split above) came from reading the code, which is worth knowing about what fuzzing does and does not buy here.
- **`hermetic_core_smoke`** — the exit criterion of the host-services work as an assertion: a core built for a test touches nothing it was not given. Measured before the work, a bare `Memory` took **205 ms**, opened a real audio device, bound `localhost:6502` and opened the 32 MB CF image — for every test binary in the suite. Three sections: an empty root finds nothing and *reports* the Woz Monitor fallback; **two cores coexist in one process** with no listening socket (where "failed to bind port 6502" used to appear), and `resetMemory()` opens none either; and an injected root that HAS a ROM is actually used (a distinguishable 256-byte image lands at `$FF00`). §4 closes the audio half: a core built on a `pom1::NullAudioService` talks to the service it was given, registers its cassette on it at activation (not at construction — the deck rides its own rail), and **hands every source back in `~Memory`**, which is what makes an injected service that outlives the machine safe. The 133 ms that item was blamed on the audio object turned out not to be it: measured in a test build, `AudioDevice(false)` costs **0.07 ms** and the first `pom1::SID` costs **~120 ms** (libresidfp's filter tables; 0.46 ms for every SID after it, per process). §5 closes that half in turn — **`Memory` no longer builds the SID chip at all** (`Memory::sidChip()`, below), so a bare core comes up in **0.3 ms** where it took 135 ms, and the section pins both halves: the construction budget (60 ms, with no "is the chip built?" accessor to assert on — `memory_public_methods` is frozen — so the observable is the one that mattered) and the functional half, that plugging the card builds the chip **and** registers it on the injected mixer.
- **`portal_file_dialog_smoke`** — the Linux desktop-portal picker against a **fake portal on a private `dbus-daemon`** whose config has no service directories, so no real portal can be activated behind the test. The fake plays the real one's part: answers `Properties.Get(version)`, replies to `OpenFile`/`SaveFile` with the Request path derived from the CALLER's unique name and `handle_token`, then emits `Response` on it. Pins the trap that fails silently and forever — the answer is a signal on a path the client must predict and subscribe to before calling — plus URI percent-decoding, Cancel (1) and window-closed (2) striking nothing, the options sent (title, folder as `ay`, suggested name, filters + All files), a portal error handing the SAME request to zenity, every backend failing leaving POM1's browser with its "could not start" hint, and (in fresh child processes) the "install zenity or kdialog" hint vs `POM1_FILE_DIALOG=builtin`'s silence. The pump doubles as a 12 s watchdog so a broken match rule fails with a sentence instead of a ctest timeout; the fake and the bus die with the test (`PR_SET_PDEATHSIG`), or a failed assert would leave them holding ctest's output pipe. Skips (77) without `dbus-daemon` or libdbus-1. Checked against the real GNOME portal by hand: pick, cancel, save with suggested name, and `WM_TRANSIENT_FOR` = POM1's window.
- **`native_file_dialog_smoke`** — the Linux picker's WAIT, not its UI. POM1 links no GTK/Qt: it forks `zenity`/`kdialog` and reads the path off a pipe, on the render thread — so the blocking wait it used to do froze the window for as long as the dialog was up and GNOME reported POM1 as not responding. Testable without a desktop because the backend is just a child process: a fake `zenity` on `$PATH` (prepended, never replacing it — a replaced `$PATH` leaves the fake script with no `sleep`, and the "slow" child then answers instantly, silently defeating the test) stands in for the real one. Four sections: a slow picker is pumped *throughout* rather than once at the end, the pumped path still round-trips the child's answer, a cancel is still a clean `false`, and with no pump installed the old blocking wait still works. Linux-only — the Win32/Cocoa backends run their own modal loop and never fork.
- **`resource_locator_smoke`** — the search order as a value (`ResourceLocator.h`, above). Seven sections: roots consulted in order with first-hit-wins, a miss being an empty path rather than a guess, `findDirectory()` refusing a file, an absolute path returned unrewritten, `rootedAt()` seeing nothing outside its root, a non-existent root being skipped rather than fatal, and `defaultLocator()` deduplicating its roots and **following a chdir**.
- **`memory_image_loader_smoke`** — the three dialects as pure functions (`MemoryImageLoader.h`, above), no `Memory` and no file in the binary. Ten sections pin what each branch exists to prevent: zone merging (else `chess.txt` becomes one zone per 8-byte row), the 1-2 digit token before `:` staying **data** (else mandelbrot-65 et al. scatter across zero page), both merged-token branches, Intel HEX detected by **shape** with a WOZMON dump named `.hex` untouched, TurboType selected by extension **or** a lone `T` — including a pin on the shredding a marker-less `.tur` suffers under the legacy parser, so the selection rule cannot quietly widen — the bare `X` marker keeping its trailing run address, odd-nibble reporting, the 64 KB clamp, **twice** that a rejected image carries no writes, the checked address accumulator (both dialects), the odd-run location and the size cap at and past the limit.
- **`staged_card_configuration_smoke`** — the UI's card-configuration transaction (`StagedCardConfiguration.h`, above). Pins that an untouched transaction has nothing to commit (the BBS regression), that the first `stage()` seeds cards + board options from the live machine so an amend adds rather than replaces, that a wholesale `cards` assignment still wins (`applyMachineConfig`), that `clear()` preserves `mode`, and that `stage()` seeds once per transaction. Links nothing but the header — the point is that this decision is reachable without ImGui.
- **`layout_decisions_smoke`** — the layout and fullscreen ARBITRATION (`LayoutDecisions.h`, above), pure: no ImGui, no GLFW, no window manager in the binary — it links only `WindowGeometry.cpp`, and only so §4 can round-trip a decided geometry through the REAL sidecar writer and parser (a field can be decided correctly and then dropped by the format; `fullscreenMode` is exactly that shape, since it arrived after the legacy two-field form). Eight sections: the windowed rect is only ever sampled from a windowed frame, what gets persisted (kiosk exemption, macOS space, `GLFW_MAXIMIZED` inside one), all five restore branches, the round trip, a layout reset and its dropped `Apple 1 Screen` placement, forced-vs-consumed placements, the checkbox against AppKit's animated exit (latch, timeout, swallowed second click), and the OS window size including the Fantasy floor's deliberate absence on WASM. This is the test the six august-2026 fullscreen defects had nowhere to live in.
- **`preset_decisions_smoke`** — what applying a preset means (`PresetDecisions.h`, above), pure, but linking the **real** `MachinePresets.cpp`: the assertions are about the thirteen machines POM1 ships rather than about fixtures, which is what makes "the shipped table exercises every branch" assertable at all. Eight sections: the silicon bundle is all-or-nothing and exactly the two multiplexing profiles disarm it (`PLabFantasy` + `Pom1Fantasy` — **not** one, which is what the first draft of this test asserted and the table refuted), the preset path and the master button compose byte-identical bundles, the strict 8 KB ceiling, the ROM profile over all thirteen, the ROM INVENTORY agreeing with that profile branch by branch (the drift pin — two copies of one predicate is a Memory Map that can describe a machine other than the one running), which preset preloads which tape and which of them is DATA, the DevBench/banner predicates, and the cold-reset rule including its silicon exception on first apply.
- **`shortcut_table_smoke`** — the key bindings (`ShortcutTable.h`, above). Links **nothing at all**: the table is a header of `constexpr` data. Six sections: every row is usable (a null command is a key POM1 grabs and then drops), lookup discriminates on key AND mods (F5 vs Ctrl+F5 is a soft reset versus a power cycle that clears RAM), autorepeat belongs to the row, no chord is claimed twice, every `Command` is bound exactly once — and the CTRL+letter invariant is asserted **with a control case**: a hand-built table carrying `Ctrl+C` must be detected, and a `Ctrl+F5` one must not, because a predicate only ever asked about a table it passes reads as coverage while providing none (the same argument `lock_order_smoke` makes for its forked inversions).
- **`file_browser_decisions_smoke`** — POM1's OWN file browser as decisions (`FileBrowserDecisions.h`), pure, linking nothing. Every section is a defect Uncle Bernie hit while developing GEN2 demo software on a Linux Mint 17 box whose native picker POM1 could not use: the browser was **confined** to the packaged data directory (`..` suppressed at `softAsmRoot` on purpose — and inside an AppImage that root is the read-only `/tmp/.mount_*` self-mount, his "weird .tmp path"), and a **typed** path did not set the loader while a **clicked** one did, so a raw `.bin` went to the WOZMON text parser and was refused on a perfectly good file. Five sections: the loader a path implies, an unknown extension implying **nothing** (asserted in both wrong directions — "always hex" mis-parsed his binary, "always binary" would write a hex listing's ASCII into RAM), `~` expansion including the three forms that are **not** ours to expand, the header reading absolute once outside the root (the old form printed `software/` plus a substring offset taken from the root's *length*), and `..` ascending to the filesystem root and **terminating** there. Its companion is `native_file_dialog_smoke` §5, which pins the other half: a picker that cannot run disarms itself so the caller falls back rather than doing nothing.
- **`software_dir_rules_smoke`** — the source-directory → card mapping (`SoftwareDirRules.h`, above), both directions, linking nothing. Six sections: every rule usable and each card a picker default at most once, component matching under both separators and a mix (plus the four near-misses — prefix, suffix, no leading separator, no trailing one), every shipped directory resolving to its card while an ordinary program folder resolves to none, first-match-wins, the reverse direction including the ambiguous two-content-card machine that must leave the picker at the `software/` root, and the round trip from every picker default back through `matchPath`. Its companion is `bbs_autodial`, which drives the same rule end to end with a real modem and a real listener.
- **`terminal_timing_smoke`** — the display busy model (`TerminalTiming.h`, above), pure, linking nothing. Five sections, of which §3 is the one that made the change safe to make: under FieldSync the wait varies with the phase — that is the point — but the WRITE-TO-WRITE interval does not, so a program printing as fast as the machine allows still prints exactly one character per field whatever phase it started at and however many cycles its poll loop burns. Without that, switching models would silently change the throughput of every printing program in the corpus. §1 pins the 17030-vs-17045 gap; §4 pins that a write landing exactly on the boundary has just missed the latch and waits a full field (returning 0 would let a tight ECHO loop print with no spin at all). The WIRING is pinned separately, in `pia_ddr_smoke` §9 — the pure test cannot see whether `Memory` actually consults the model, and that section distinguishes the two by construction: after one 17030-cycle field FixedDelay is still busy and FieldSync never is.
- **`bbs_autodial`** — the user-visible end of the same regression, offline (`tools/test_bbs_autodial.py`). Phase A reads both shipped `software/NET/bbs.*.txt` dumps as text and pins load address `$0280` + a NUL-terminated `ATDT <host>:23`. Phase B runs the SAME program with only its dial target rewritten to a listener the harness owns on `127.0.0.1`, and asserts the loader reports run `$0280`, the modem logs the dial, the emulated display shows the echoed `ATDT` and the modem's `CONNECT`, and the fake BBS accepted **exactly one** connection. No Internet is used or needed. It does NOT guard the staging decision — that lives in the UI, which no test binary links.
- **`extended_aci_smoke`** — Uncle Bernie's Extended ACI end to end: pins the `$C500` mapping / write-protect / ACI cascade *both ways*, then plays his own `cassettes/codebrk.aiff` through the real pulse path, types `C500R` + `RX RX`, and asserts Codebreaker autostarts (banner on `$D012`). Also the **only** gate on POM1's hand-rolled AIFF reader.

**CMake layers and test build model.** The dependency direction is materialised
as INTERFACE targets: `pom1_ui` → `pom1_app` → `pom1_devices` → `pom1_core`.
They initially carry usage requirements while source ownership migrates out of
the historical executable; this avoids changing runtime behaviour in a build
refactor. The 24 device sources every integration test needs
(`POM1_TEST_CORE_FILES`) are compiled once into the `pom1_test_devices` OBJECT
library declared in `tests/CMakeLists.txt`; its separate identity is deliberate:
tests inherit `-UNDEBUG`, while the Release app keeps `NDEBUG`. Sharing those
objects would silently disarm test assertions or arm them in production. The
common `pom1_add_smoke_test()` helper is used as test families migrate to the
smallest logical layer. A configure-time pass binds every executable consuming
`pom1_test_devices` to `pom1_devices` and aborts if object use and layer
declaration ever diverge. Before object sharing, a full build ran 1435
compilations, 1154 of them redundant (`TMS9918.cpp` compiled 53 times); it is
now about 355.

**Architecture trend guard.** `tools/check_architecture.py` (CTest
`architecture_check`) rejects any new direct include from the core/device set
toward ImGui or `MainWindow` and reports ceilings for `Memory`,
`EmulationController`, the `MainWindow_*` family, selected header fan-out and
sources outside `pom1_test_devices`. The checked-in
`tools/architecture_baseline.json` is a ratchet, not a target architecture:
lower a ceiling when a refactor improves it; never raise one merely to make CI
green. A deliberate new dependency requires an architectural review and an
explicit `allowed_reverse_dependencies` entry.

Two ratchets sit alongside it, both grandfathering what exists today rather
than describing a target:

- **The devtools boundary** — `DEVTOOLS_DIRS` / `DEVTOOLS_STEMS` name the
  development environment (`src/{bench,hgrpaint,hgrsprite,tmspaint,tmssprite,sfxbeep,sidtrack}/`,
  the `Pom1*Host` files, the BASIC compilers, `DbgFile`, `BenchDebugSession`),
  and every include of one of their headers from outside that set is an edge in
  `allowed_devtools_dependencies`. There are **17**, in four files, all
  `MainWindow_*` — that is what makes the `-DPOM1_DEVTOOLS=OFF` work bounded,
  and the ratchet is what keeps it bounded while it waits. A new edge fails; so
  does an edge left in the baseline after its last call site is gone, so the
  list can only shrink.
- **Frozen facades — and the septembre-2026 exception, which is the interesting
  part.** `memory_public_methods` (190) and
  `controller_public_methods` (203) count declarations at class scope in
  `Memory.h` / `EmulationController.h`. The count, not the line total, is the
  property that matters: a facade shrinks by losing methods, and the old
  line-based ceilings say nothing about how much a caller can ask of the
  object. `Memory` was **frozen** (TODO.md chantier 2) — no new public method,
  no new `Memory.h` include — and `EmulationController`'s per-card passthroughs
  come off one at a time as their last caller goes (chantier 4). The audio-seam
  work is what that distinction is for: it kept `memory_public_methods` at 188
  (the injected service arrived as a third defaulted constructor parameter, not
  an overload) while `memory_lines` went **3934 → 3965**, and those 31 lines ARE
  the seam — the owned/borrowed pair, the constructor branch and the destructor
  that unregisters sources. That is the only kind of raise a ceiling here takes:
  one that names what bought it — the lazy SID is the second (`memory_lines`
  3965 → 3990, `controller_lines` 3079 → 3089, `memory_public_methods`
  unmoved at 188: those 35 lines are `sidChip()`, its two `mutable` members
  and the controller's deliberate pre-lock warm-up).

  **The freeze was then lifted once, deliberately, by the maintainer**, for the
  Apple-1 display busy model (`src/TerminalTiming.h`): `memory_public_methods`
  188 → 190 (`setDisplayBusyModel` + `displayBusyModel`),
  `controller_public_methods` 201 → 203 (`setDisplayFieldSync` +
  `isDisplayFieldSync`), plus the line ceilings. The first draft honoured the
  freeze by routing the model through a defaulted constructor parameter, exactly
  as the audio seam had; that costs the live toggle, and the call was made that a
  fidelity knob nobody can flip while the machine runs is not worth the purity.
  Recorded here rather than quietly edited into the JSON, because a ceiling that
  moves without a reason in the file is how a ratchet stops meaning anything.

  **`memory_lines` 3988 → 4041 is the third**, and it buys the card-shadow
  warning: `warnIfCardsShadow` in `Memory.cpp` plus its two call sites, one in
  each loader. `memory_public_methods` does not move (190) and no new consumer
  of `Memory.h` appears — the freeze is on the FACADE, and a file-local helper
  that walks a registry `Memory` already owns is not one. It lives there rather
  than in the UI because that is the single point all three load paths pass
  through (Load Memory, `--load`, the control channel's `load`); the decision
  it defers to is pure and outside (`src/CardShadowing.h`).

  **`mainwindow_lines` 17071 → 17098 and `sources_outside_test_devices`
  88 → 89 are the fifth**, and they buy the DYNAMIC PRESET TABLE (below):
  every site holding a user-supplied preset index goes through
  `machinePresetAt()` and returns early on `nullptr` instead of indexing a
  fixed array, which is three lines apiece at nine sites, plus `PresetLoader.cpp`.
  Worth naming precisely because the earlier estimate was wrong and had been
  used to decline the work twice: `kMachinePresets[` appears 57 times, but only
  **13** are real indexing sites and only **9** take an index that came from a
  user — the rest are declarations, comments, tests, and lookups by a named
  constant that are provably in range. A count of mentions is not a count of
  couplings, and the difference here was the difference between "wide refactor"
  and an afternoon.

  **`mainwindow_lines` 17056 → 17071 is the fourth**, and it is the cheaper
  side of a trade. External preset files (`src/PresetFile.h`) need a machine
  applied that is not a `kMachinePresets[]` row, so `applyHeadlessConfig` split
  into an index form that looks the row up and a `MachineConfig` form that does
  the work; the alternative was a second copy of the twenty-five lines that
  build a `CardConfigurationRequest`, in `main_imgui.cpp`, where no ceiling
  would have counted it. Fifteen lines of ratchet against a rule stated twice is
  the trade `PresetDecisions.h` exists to make — and the same pass raised
  `sources_outside_test_devices` 87 → 88 for `PresetFile.cpp` itself.

  **`EmulationController.h` fan-out 17 → 18 is the sixth**, and it is the
  cheapest kind: a TEST. `rewind_seek_cost_smoke` asks "what does a rewind seek
  do to the machine?", which cannot be asked without the controller that owns
  the rewind buffer. Same shape as the 58 → 59 raise `hermetic_core_smoke`
  bought — the metric counts `tests/*.cpp` on purpose, and a test whose subject
  IS the object must include it.

  **The scripting control channel is the counter-example, and the shape to
  copy**: it added a whole new externally-reachable surface — twenty verbs
  covering memory, the CPU, the keyboard, the display and snapshots — and moved
  `controller_public_methods` by **zero**, because every verb was reachable
  through facade API that already had another caller and the file-shaped ones
  reuse `CliDispatcher`. What it did cost is named above:
  `sources_outside_test_devices` **86 → 87** (`CommandPort.cpp`) and
  `EmulationController.h` fan-out **15 → 17** (the channel and
  `command_port_smoke`). A debug channel is exactly the kind of consumer that
  must live OUTSIDE a frozen facade; if the next one needs a new public method,
  that is the signal the facade is missing something its existing callers also
  want, not a licence to raise the count.

New invariant tests follow `tests/peripheral_bus_smoke_test.cpp` — `<cassert>` + `add_test` suffices; GTest/Catch2 only once multi-threaded tests land.

**The seven `tools/test_*_telnet.py` harnesses are no longer manual** — they run in `ctest -L emulator` as `iec_daughterboard`, `logo_interpreter`, `sdcard_subdir_navigation`, `cffa1_compactflash`, `aci_cassette_roundtrip`, `jukebox_program_manager` and `sdcard_os_commands`: **48 s for 198 assertions**, each skipping with 77 when its fixture is absent, all `RUN_SERIAL` (they drive a whole emulator each). They keep the `_telnet` name because that is what they were; they now go through `--cmd-port` (above) via `tools/pom1_control.py`, which launches and reaps its own headless POM1 on a free port. **What made them unrunnable was four things at once**: a hardcoded port 6502 (so they fought any POM1 the developer had open, and each other), no `--headless` (so no display-less box could run them), three of them assuming an operator had already launched POM1, and forty `time.sleep()` calls standing in for "has the machine got there yet?". Converting them found six defects — the headless tape gap above, CFFA1 entered at `$9006` while asserting `$9000` behaviour, three sets of expectations frozen against ROM/disk images that have since been rebuilt, and a LOGO harness pointing at a build artefact that stopped existing in juillet 2026. **The lesson worth keeping is about pinning generated content**: the Juke-Box catalogue is now PARSED and checked for the shape the firmware promises, because a hand-written list of a generated ROM's contents rots at every rebuild — and rotted unnoticed precisely because the test never ran.
